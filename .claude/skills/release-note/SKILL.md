# Release Note Generator

git 변경 이력을 분석해 기술 용어를 걷어내고, 사용자가 이해할 수 있는 언어로 플랫폼별(App Store / Play Store) 릴리즈 노트 초안을 작성한다.

---

## 핵심 원칙

1. **사용자 언어** — "ViewModel", "Repository" 같은 기술 용어 노출 금지. 체감 변화로 번역.
2. **가치 중심** — "무엇을 바꿨는가"가 아닌 "사용자에게 무엇이 좋아졌는가"를 서술.
3. **플랫폼 제약 준수** — App Store 최대 4,000자 / Play Store 최대 500자. 초과 시 경고한다.
4. **포함·제외 기준 엄수** — 내부 리팩토링, 테스트, DI 변경은 제외한다.
5. **추측 금지** — 사용자 가치가 불분명하면 질문한다.
6. **사전 확인** — 초안 출력 후 반드시 사용자 승인. 파일 저장은 명시적 요청 시에만.

---

## 범위 결정

`$ARGUMENTS` 값에 따라 분석 범위를 결정한다.

| `$ARGUMENTS` | 분석 범위 |
|---|---|
| 없음 | 가장 최근 태그 ~ HEAD |
| 태그 1개 | 해당 태그 ~ HEAD |
| 태그 2개 | 첫 번째 태그 ~ 두 번째 태그 |
| 커밋 해시 1개 | 해당 커밋 ~ HEAD |
| 커밋 해시 2개 | 첫 번째 커밋 ~ 두 번째 커밋 |

---

## 실행 프로세스

### 1단계: 범위 파악

```bash
git tag --sort=-version:refname | head -5
git describe --tags --abbrev=0
git log <from>..<to> --oneline --no-merges
git log <from>..<to> --format="%H%n%s%n%b%n---" --no-merges
```

| 상태 | 처리 |
|---|---|
| 태그 없고 범위 미지정 | from 범위를 사용자에게 요청 |
| 커밋 없음 | 알리고 중단 |
| 커밋 1~30개 | 정상 진행 |
| 커밋 31개 이상 | 계속 여부 확인 |

### 2단계: 커밋 분류

**포함** (사용자에게 보이는 변경)

| type | 카테고리 |
|---|---|
| `feat` | 신규 기능 |
| `fix` | 버그 수정 |
| `perf` | 성능 개선 |
| `ui` | UI/UX 개선 |

**제외**: `refactor`, `test`, `chore`, `docs`, `ci`, `style`

**특수 케이스:**
- `BREAKING CHANGE:` body → `⚠️ 확인 사항` 카테고리
- `revert:` → 원본과 쌍으로 제외. 원본이 범위 밖이면 사용자 확인
- type 없는 커밋 → subject로 판단, 불분명하면 제외
- 경계 케이스 (`chore: 보안 패치`, `refactor: 로그인 플로우 재구성`) → 사용자 확인
- 포함/제외 판단 어려운 커밋이 3개 이상 → 목록을 보여주고 일괄 확인

### 3단계: 기술 용어 → 사용자 언어 번역

#### Scope 번역 기준

| scope | 사용자 표현 |
|---|---|
| `feature/home` | 홈 화면 / 홈 피드 |
| `feature/auth` | 로그인 / 회원가입 / 인증 |
| `feature/profile` | 프로필 / 내 정보 |
| `feature/settings` | 설정 / 앱 설정 |
| `feature/search` | 검색 |
| `feature/notification` | 알림 |
| `feature/onboarding` | 앱 첫 실행 / 시작 화면 |
| `core/network` | 앱 연결 안정성, 자동 재시도 |
| `core/storage` | 데이터 저장 안정성, 로딩 속도 |
| `core/navigation` | 화면 이동 / 뒤로 가기 동작 |
| `domain/[name]` | 해당 기능 이름 (예: `domain/user` → 계정) |
| `data/[name]` | subject에서 사용자 가치 추출, 불가 시 제외 |
| `app/*` | 원칙적 제외. 성능/안정성 개선 목적이면 포함 가능 |

#### 카테고리별 문장 패턴

**✨ 신규 기능**: `이제 [기능]을 [동작]할 수 있습니다.`
- 이제 알림을 화면에서 직접 끄고 켤 수 있습니다.
- 프로필 사진을 직접 변경할 수 있습니다.

**🛠️ 개선 사항**: `[기능]의 [무엇]이 개선됐습니다.` / `[상황]에서 [동작]해 [효과]를 줄였습니다.`
- 홈 피드 로딩 속도가 개선됐습니다.
- 불안정한 네트워크 환경에서 자동으로 재시도해 오류 발생을 줄였습니다.

**🐛 버그 수정**: `[상황]에서 [문제]가 발생하던 문제가 수정됐습니다.` / `이제 [상황]에서 [정상 동작]합니다.`
- 로그인 오류 발생 시 앱이 종료되던 문제가 수정됐습니다.
- 이제 뒤로 가기 버튼이 모든 화면에서 올바르게 동작합니다.

**금지 표현**: "버그를 수정했습니다"(모호), "크래시"(부정적), "혁신적인"(과장)

#### 자주 하는 실수

| ❌ | ✅ |
|---|---|
| ViewModel 상태 관리를 개선했습니다 | 화면 전환이 더 안정적입니다 (또는 제외) |
| Repository 캐시 로직을 추가했습니다 | 데이터 로딩 속도가 개선됐습니다 (또는 제외) |
| DI 설정을 업데이트했습니다 | 제외 |
| 다양한 개선 및 버그 수정 | 구체적 항목으로 분리 |

### 4단계: 정렬 및 초안 작성

정렬 기준: 사용자 영향 범위(전체 앱 > 주요 화면 > 세부 기능) → 체감 강도.

#### App Store (최대 4,000자)

- 항목당 1~2문장 (30~60자 권장), 해당 카테고리 없으면 섹션 생략
- 어조: 친근하고 긍정적. 과도한 홍보 피한다

```
이번 업데이트에서 달라진 점

⚠️ 확인 사항
• [사용자 조치가 필요한 내용]

✨ 신규 기능
• [기능 이름]: [사용자 혜택 1~2문장]

🛠️ 개선 사항
• [개선 내용 1~2문장]

🐛 버그 수정
• [수정 내용]
```

#### Play Store (최대 500자)

- bullet point(`•`) 목록만, 헤더 없음
- 항목당 15~30자, 3~7개. App Store에서 핵심 항목만 선별
- 500자 초과 시 사용자에게 제거 항목 확인

### 5단계: 초안 출력

```
**분석 범위:** <from> ~ <to>  
**포함된 커밋:** N개 (feat: N, fix: N, perf: N)  
**제외된 커밋:** N개

---

### App Store (약 NNN자 / 4,000자 제한)

<초안>

---

### Play Store (약 NNN자 / 500자 제한)

<초안>
```

출력 후 수정/추가/제외/파일 저장 여부를 확인한다. 수정 시 양쪽 플랫폼 초안을 다시 출력한다.

### 6단계: 파일 저장 (선택)

사용자 요청 시에만 `release-notes/<version>.md`에 저장.

---

## 금지 사항

- 커밋에 없는 내용 임의 추가
- 내부 변경을 사용자 기능 변화로 포장
- 글자 수 제한 미확인 출력
- 사용자 승인 없이 파일 저장
- `fix` 커밋을 부정적 어조로 서술
